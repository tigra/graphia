> **Read the tech spec's two opening notes before starting.** Spec 028 is the template for almost everything here — **but its §2.1 replay-safety argument does not transfer**, because there is no `interrupt()` at the Day→Night hinge. Do not copy that reasoning; §2.1 of this spec argues the dedicated node on different grounds.

> **HARD PREREQUISITE, and its failure mode is silent.** `tests/conftest.py`'s `FakeLargeUnified` has no `Diary` queue. Without one, `with_structured_output(Diary)` raises `AssertionError` — and **the node's own `try/except` swallows it into the deterministic fallback**, so a test measures `_DIARY_FALLBACK` and passes while proving nothing. Slice 1's first task adds the queue and a regression test that a flag-on run produces a *real scripted entry*, not the fallback. Nothing else in this spec is trustworthy until that lands.

> **Three names, three things — a collision that will otherwise cost an hour.** `graphia.diary_store.DiaryEntry` already exists. Use `Diary` (structured-output schema, `llm.py`), `DiaryRecord` (state entry, `state.py`), `DiaryEntry` (store DTO, **unchanged**).

> **Naming is fixed and single-spelled** from env var to ledger key: `GRAPHIA_PRIVATE_DIARIES` → `private_diaries_enabled` → `private_diaries` → `settings.private_diaries_enabled`.

> **Baseline to hold:** `uv run pytest -q` at **1561 passed, 1 skipped** in the main checkout (a fresh worktree reads 1554/8 — the 7 extra skips are `test_lambda_zip_contents.py`, whose build artifact is gitignored; do not investigate them).

## Notes for the implementer

- **A shared expected-value literal can hide a mutation that a per-fixture one catches — proven, not theorised.** Slice 5's M13 made the `scripted_player` drill-down line unconditional. It was caught by the two fixtures **lacking** the field and **not** by the one carrying it. Appending the label to the shared `_SETTINGS_FIXED_LABELS` literal — the obvious fix — would have made all three params expect the line, and M13 would have survived on all three. When a conditional render is under test, the expectation has to vary per fixture.
- **Do not pin a corpus census as a count when a later slice will change it.** Slice 5 verified "0 of 30 committed records carry the arm" but pinned the durable **iff** rule instead (a record renders the line exactly when it carries the field, plus an at-least-one guard so the absent branch is provably exercised) — because Slice 6 appends six records that *do* carry it, and a `== 0` would then go red for a good reason. Same lesson as Slice 4's dormant guards, applied forwards.

- **Pre-existing, NOT introduced by spec 039 — a `textual-ansi` contrast finding for whoever owns that theme.** In `render_lines`, every kind whose CSS names a theme variable composites to literal `#000000` under `textual-ansi`, while genuinely unstyled `plain` text keeps `Color('default')` — roughly 1.6:1 against the ground, well under AA. Verified **uniform** across `marker`, `attr`, `field-label`, `thought`, `recap` **and** `diary` in the same run, so the diary is no worse off than the sibling it was modelled on. It may also be partly an SVG-export artifact: the app's own resolved style is `Color('default')`, i.e. SGR 39, which a real terminal paints in its own foreground. A fair follow-up candidate; out of scope for this spec.

- **A guard that imports the constant it checks cannot catch that constant being renamed.** Slice 4's mutation M2 renamed `KIND_DIARY` to `"journal"`; the viewer's style-map completeness guard stayed **green**, because it reads the constant and renames along with it. Only the bare-literal pin (`KIND_DIARY == "diary"`) fires. This is the vacuity shape demonstrated rather than argued — pair every constant with a literal.
- **DORMANT GUARDS THAT SLICE 6 WILL BE THE FIRST TO EXERCISE.** Three assertions are correct today *only* because `day="` and `<diary` occur **zero** times in the 298 committed transcripts: `_ACHROMATIC_ATTR_KEYS`'s `day` row, the corpus sweep's inline-body `elif` arm for `KIND_DIARY`, and the "`day` is the one whitelisted name the corpus may be missing" claim. All three are written to stay true once diaries-on transcripts land — **so a failure there is real data disagreeing with the rule, not test rot.** Read it that way before "fixing" the test.
