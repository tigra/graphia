# Tasks: Colour-Coded Transcript Reading View

- **Functional Specification:** `./functional-spec.md`
- **Technical Considerations:** `./technical-considerations.md`

> **Verification is headless `pytest` only.** The tokenizer is a pure function, so most of the work is verified without a terminal at all; the UI half goes through Textual's `App.run_test()` harness — the project's established convention in `tests/test_ledger_viewer.py`. **No browser or external MCP is needed and none is missing.** Nothing here reaches a model, the network, or the ledger.

> **Facts already verified against the source and the committed corpus** — do not re-derive, but do not contradict either. The corpus under `evals/transcripts/` holds **298** files: **268** in the spec-022 form (`<player name="…" role="…">`) and **30** pre-022 (indented `Name — Role`). `<vote …>` appears in **264** of them and `<thought player="…">` in **216** — **absence is normal, not corruption**. `Moderator: A new game begins. Welcome, <name>.` and `(no persona recorded)` each appear in **all 298**. **No transcript contains a `[` today** — which is exactly why `markup=False` must stay: persona prose is model-generated and the next one may.

> **Ratified during Slice 1 — the marker vocabulary is TWELVE tags, not the eight the task text lists.** The eight enumerated (`<transcript>`, `<setup>`, `<preamble>`, `<night>`, `<day>`, `<round>`, `<endgame>`, `<kill>`) are the *attribute-free, content-free* subset; `<player …>`, `<vote …>`, `<recap>` and `<thought …>` are markers too, from Slice 1 onward. The tech spec is only self-consistent this way: its `attr` row defines `attr` as the values "inside a **marker**", and Slice 3 requires a thought's "surrounding tag **stays** `marker`". Had those four been `plain` in Slice 1, Slices 2-3 would have to promote whole lines out of `plain` — the rewrite the slicing exists to avoid — and a game would render with `<setup>` dimmed while each `<player …>` inside it read as content. **An inline `<tag>content</tag>` yields three spans** (opening `marker`, content, closing `marker`), except `<kill>` whose content is also `marker` and therefore coalesces back to one span. Do not write a test asserting `<player …>` is `plain`.

> **Ratified during Slice 1 — how a kind becomes an appearance, for every later slice's styling task.** The kind → style map is `_TRANSCRIPT_KIND_COMPONENTS` in `src/graphia/ui/ledger_viewer.py`: `kind → Textual component-class name`, one CSS rule per entry in `TranscriptScreen.DEFAULT_CSS`, resolved to Rich styles by `TranscriptScreen._kind_styles`. Adding a kind is one dict entry plus one rule. **Two traps, both measured on the installed Textual 8.2.4, not inferred:** (1) `get_component_rich_style(name, partial=True)` returns the rule's properties *unresolved* — `$text-muted` comes back `#ffffff` instead of the `#a0a0a0` the same rule renders — so the **full** style is required and its baked-in background is stripped afterwards (`without_color + Style.from_color(color)`); (2) a kind absent from the map appends with `style=None`, i.e. renders unstyled and never raises, which is why `plain` needs no entry. Under the `textual-ansi` theme every theme variable resolves to the terminal default, so markers are legible but not distinguishable there — a known, accepted degradation of that one theme.

> **Slice 1 writes the corpus round-trip property test first.** It is the cheapest exhaustive test in the spec: read-only over 298 real files, no fixtures to author, and it covers both formats and every element-presence combination the corpus actually contains. It makes *"the stored game is never altered"* (functional-spec §2) structurally true rather than merely intended.

## Notes for the implementer

- **The round-trip invariant is the spine of this spec, not a nicety.** `"".join(text for text, _ in spans) == original`, asserted over all 298 committed transcripts, is what makes the "stored game is never altered" requirement structural. Every slice adds kinds; every slice must leave it passing. A dropped or duplicated character is invisible against a wall of text and would otherwise ship.
- **`markup=False` is not negotiable.** Spans only. The corpus contains no `[` today, but persona prose is model-generated, and the existing comment in `TranscriptScreen.compose` already names this hazard.
- **`$text-muted` is right here and was wrong in spec 037.** It resolves to `auto 60%`, which the CSS parser **rejects** for `border:` — and a screen whose CSS fails to parse never mounts (that mistake cost 15 test failures in 037). This spec sets `color:` only, where it is the module's own precedent.
- **Assert span structure, not rendered colour.** Colour is theme-dependent and a poor test subject; 037 established this. Appearance is reviewed by eye, structure is asserted programmatically.
- **Relative equality alone can be vacuously true (037's mutation finding).** An assertion of the form "X equals Y between two states" can hold while both are broken identically. Where a test compares two tokenizations, also pin absolute expected spans.
- **Absence is normal.** 34 files have no `<vote>`, 82 have no `<thought>`, 30 have no `<player>` tag at all, and — **found in Slice 1** — only **278 of 298** have an `<endgame>` tag: in the pre-022 era the ending is folded inside the trailing `<night>` block instead. Relatedly, **no transcript ends with a newline** (all 298 end on `>`), so a tokenizer that appends a newline per line fails the round trip on every single file. A tokenizer that assumes presence passes its synthetic fixtures and breaks on real data — which is why the corpus test exists.
- **Keep `eval_ledger.py` free of Rich and Textual.** Verified today: zero matches. That is the property which lets the parsing — the part most worth testing — be tested as a pure function with no terminal.
- **Spec 037 is Completed**, so `ledger_viewer.py` is uncontended now; the two specs touch different classes and 037 deliberately left `TranscriptScreen`'s rendering alone for this one.
- **Textual 8.x's native renderable is `Content`**, not Rich's `Text`. A Rich `Text` is **verified working today** — `Static.render()` returns a `Content` with the spans preserved — so use it, but a future refactor may prefer building `Content` directly.
- **Suite baseline differs by tree, and both numbers are correct.** In the main checkout it is **1289 passed, 1 skipped** (the 1 skip is the opt-in live-observability test). In a **fresh worktree** it is **1282 passed, 8 skipped** — the 7 extra skips are all `test_lambda_zip_contents.py`, which skips when `infra/lambda/.build/*.zip` is absent, and that artifact is gitignored so no fresh checkout has it. Do not investigate those skips, and do not key a later task off the wrong tree's number.
